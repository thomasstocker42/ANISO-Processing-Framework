# R2PRIME01 — R2-prime input inventory and geometry validation

**Status:** Finalized

**Production implementation:** R2PRIME01 v0.2.0

## Purpose

R2PRIME01 defines and validates the authoritative inputs required to
construct R2-prime for susceptibility source separation.

The downstream quantity is

\[
R_2' = R_2^* - R_2.
\]

In the present pipeline, the high-resolution dual-echo apparent
relaxation-rate map generated by RLX05 is used as the spatial surrogate
for R2. Therefore the production pipeline will construct

\[
R_2' = R_2^* - R_{2,\mathrm{app}}^{GRE}.
\]

R2PRIME01 does not perform registration, interpolation, resampling, or
R2-prime calculation. Its role is restricted to provenance, readiness,
input integrity, and native-geometry validation.

## Prerequisites

- RLX01 — authoritative relaxometry input inventory
- RLX05 — high-resolution dual-echo R2app reconstruction
- RLX06 / RLX06b — validation of dual-echo R2app against the 12-echo R2 reference
- GRE02b — GRE first-echo magnitude and GRE reference geometry
- R2STAR02 — production multi-echo GRE R2star reconstruction

## Authoritative inputs

### Dual-echo TSE

The dual-echo TSE source is inherited from RLX01 selected-input metadata.

Requirements:

- `dual_tse.ready = true`
- `dual_tse.selected = true`
- exactly two echoes
- echo order defined by `echo_number`
- source images present and readable

For the current InS cohort:

- TE1 = 13 ms
- TE2 = 103 ms
- delta TE = 90 ms

The first dual-TSE echo is designated as the moving anatomical image for
R2PRIME02 registration.

### High-resolution R2app

Source:

`derivatives/<case>/relaxometry/rlx05/`

Production image:

`rlx05_<case>_R2app_s-1.nii.gz`

Units:

`s^-1`

The R2app image remains in native dual-TSE geometry at the R2PRIME01
stage.

### GRE registration reference

Source:

`derivatives/<case>/GRE/02b_brain_mask/`

Production image:

`<case>_GRE02b_magnitude_e1.nii.gz`

GRE02b magnitude echo 1 is the authoritative fixed registration image.

The first GRE echo was selected instead of an all-echo average because
it provides the highest signal level and minimizes T2star-related signal
loss and susceptibility dropout while preserving the native geometry of
the downstream GRE-derived quantities.

## Geometry contract

R2PRIME01 verifies the following native-space relationships:

1. dual-TSE echo 1 and echo 2 have identical geometry;
2. dual-TSE echo 1 and RLX05 R2app have identical geometry;
3. GRE02b magnitude echo 1 and R2STAR02 R2star have identical geometry;
4. whether native TSE and GRE geometry are identical.

Native TSE and GRE geometry are expected to differ. This is not treated
as a failure. Instead, it establishes the need for R2PRIME02
registration.

Across the current cohort, both modalities use 1 mm isotropic voxels,
but their matrix sizes / fields of view differ.

## Quantitative finite-data QC

R2PRIME01 records finite-value coverage for R2app and R2star.

Non-finite voxels outside the valid quantitative support of R2app are
permitted. The module therefore requires the quantitative images to
contain finite data but does not require all voxels in the rectangular
NIfTI image volume to be finite.

For the current cohort:

- R2app finite-data fraction: approximately 16.2% to 23.4%
- R2star finite-data fraction: 1.0 in all cases

The R2star finite-data fraction of 1.0 does not imply that the complete
rectangular image volume constitutes valid quantitative support.

The final common valid support for R2-prime will be defined downstream
after R2app has been registered into GRE space.

## Downstream contract

R2PRIME02 will estimate a rigid 6-DOF transform:

dual-TSE echo 1 -> GRE02b magnitude echo 1

Planned production settings:

- transform: rigid, 6 DOF
- registration metric: normalized mutual information
- direction: dual-TSE -> GRE
- R2app interpolation: linear
- output geometry: native GRE grid

The resulting registered R2app map will be consumed by R2PRIME03 to
construct R2-prime.
